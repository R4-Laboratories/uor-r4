# Test the source ranking before fitting the action or the writer

The zero-offset source-only certificate has 33 comparisons from 13 supported questions. It forces zero to exceed a positive number for any shared 32-word table. This supplies the first falsifier for the next representation. Giving each prompt its own weights or changing the bound, threshold, or EOS action cannot resolve it.

1. Use the already-captured state at the start of the question to test whether a passage-relative frame retains the information needed for a common ranking. In each block compare the existing query-to-zero action with the canonical D11 action taking the query root to the passage-only root. Apply that action to the same original source root. Keep the 32 i16 words, support identities, all candidates, and both offset settings. Retain swapped and removed queries plus a same-byte passage-only control. Verify the representation separately against product transitions. Test whether the old zero-sum contradiction survives, then solve *all* supported original-site comparisons even if that particular contradiction disappears. No label selects a passage boundary or a site at scoring time. For this diagnostic the serialized passages have authenticated separator boundaries. General conversations still need a causal way to locate such a boundary.
2. If a common table exists for supported rankings, reintroduce the five unsupported rows and strict NoRead. Preserve both members of each pair and check the single shared state against the fixed, swapped and removed controls. If source-only rankings still conflict, stop this frame configuration. Trace which signed site comparisons cancel and assess an existing richer native occurrence or interval representation. Changing thresholds alone addresses a different decision. Treat this panel as exposed; a new source-disjoint blind panel must confirm a fit decision.
3. A training run requires the preregistered non-author review, actual-vs-control contrast and original-address replay. Fit only on TRAIN. Reopen the integer artifact in the ordinary client. Report first wrong committed IDs, original source, retries, and exact EOS on fresh questions. Include prose and reasoning prompts as soon as the checkpoint enters ordinary chat evaluation. No fitted table from these feasibility witnesses is a model candidate.

The roadmap already reports an equal-byte Stage B2 comparison of geometric address tables with token-context baselines. Its 100 MB E8 configuration and four fallback address arms lost on DEV-tune. Reuse those receipts for those configurations. A new qualified persistent reader would need its own comparison at equal actual deployed bytes and matched training data, with full-reply quality and client memory and latency measured separately.
