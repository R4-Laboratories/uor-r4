Its two signed occupied axes contribute to the score, giving eight signed additions per candidate across 32 possible i16 words. We held the existing 513 words, original candidate addresses, NoRead score and writer fixed. The 64-byte figure is the additional table size. The broader equal-byte prediction experiments have their own full-artifact accounting. [Source, geometry checks and Wick replay](transport/README.md)

## Checks run at the head

The previous and fresh ordinary prefixes supplied 1,148 and 1,476 candidate positions, respectively. The independent finite operator checks covered 1,024 action/root cells, 256 BFS transitions, 256 normalized query/site cells, 16 anchor identities and 4,096 relative-frame checks. Reversing the fresh capture order reproduced both streams byte for byte. The archived native inverse test required a test-only import repair in a disposable checkout. The release capture used the original native functions with a visibility-only patch in the feature extractor. No shipping crate changed. [Transport verification](transport/README.md)

A separate Rust checker rebuilt the candidate inequalities from the capture and exact-address keys. It verified integer witnesses, certificate bounds and actual-table replay for 4,460 verdicts on individual rows, pairs, whole panels and row-removal checks. It verified 16 additional pooled source/NoRead splits. There were zero unknowns. Planted wrong addresses, zero proof multipliers, incorrect counterfactual flags, and an omitted verdict all failed verification. The revision-pinned private archive was downloaded again, rebuilt on Wick and reproduced the captures, grades and six verification summaries. The question now changes which source addresses the model could distinguish within an individual pair. The same weights cannot make those distinctions across passages. We preserved a small counterexample for abstention and a separate counterexample for source ranking, without spending GPU time on an impossible fit.
