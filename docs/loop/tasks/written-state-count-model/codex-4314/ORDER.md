# Fit the assistant-opening score on canonical donor targets

Codex development under [#4063](https://github.com/UOR-Foundation/uor-r4/issues/4063) and the [written-state roadmap](../../../../roadmap/items/written-state-count-model.md), following the [sealed question swaps](../codex-4313/REPORT.md). The owner requested correction of all 4,345 donor openings and an equal-budget training comparison of final colon alone against the complete assistant marker and question state, with the writer fixed.

## Scope and done check

Rebuild visible answer-first text with the ordinary protocol-2 dialogue encoder on the same 4,060 D87 TRAIN groups. Independently compare persisted prefixes, masks and answer token spans for every genuine assistant opening to ordinary serving of the original text. Keep reasoning in separate documents. Use a common corrected donor tape and a separate counterbalanced TRAIN contrast set. Freeze new disjoint question/fact assignments, entire held wording families and an independent natural transfer before fitting. Publish both answer scores and ranks under both questions and both assignments, with standalone-space scores and ranks, source state, emitted ID, abstentions or zero support and two-way preference on both assignments. Where a fresh donor answer starts with standalone space, measure that true immediate target separately from the first lexical target.

Keep one frozen native answer-first D11 trunk, all codebook coordinates, writer implementation and vocabulary in both arms. Train the new first-emission readout in each arm. Use all eligible immediate targets after a colon in the corrected tape, plus exactly the same fitted contrast events in identical order and update budget. The baseline sees the final colon alone. The treatment recognizes the complete deployed assistant marker and uses the causal geometric question state. Neither arm may see source labels, target/rival identity, a held answer or a suffix of the answer when constructing serving features. Equalize source groups, target and negative presentations, schedule, seed and budgets; report any genuine capacity difference. Retain the ordinary model path outside the fitted boundary.

## Native cycle and cancellation

Use typed original IDs, bounded integer state, learned integer scores at geometric addresses and the prior for deterministic ties. Store the native readout losslessly with the frozen model and exercise the same prediction in the ordinary Rust product and the GPU evaluator. Use a prebuilt CUDA integer kernel for fitting and held scoring. Require equality of feature addresses, decision, sparse scores, ranks and final original-ID emissions between the GPU and an independent cold product path. Demonstrate positive, negative, no-change, marker near-miss and wrong-state controls before interpreting a zero. Hold the ordinary writer fixed through all arms. Record the exact representation, training operator, packing and replay interface before authorizing the run.

Abort or repair the instrument before accepting results if donor text or IDs disagree, held rows overlap the training contrasts, features leak either answer, update budgets differ, the score ordering or writer changes unexpectedly, or reload/replay differs. The result is an opening-score comparison; qualify full-reply claims only from actual generations. The top session owns the FIT decision, recipe, GPU qualification, custody and scientific interpretation. No corpus generation by a donor model, scale increase or milestone change is in scope.
