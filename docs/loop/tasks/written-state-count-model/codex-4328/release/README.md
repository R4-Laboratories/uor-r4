# Test the release weights in the ordinary text client

The baseline collection first registered the opening source, exact first ID and actual self-fed second ID. Case c002 reached its requested original source and a native period. The conditional collection then ran *every* sealed raw prompt with the optional `--authenticated-copy --native-period-release` combination. There are three fully loaded D11 artifacts, with the same linked state below the additional zero, row-wise or paired residual. [Pre-run review](FIT.md) · [Inputs and invocation](run.sh)

The CLI retains the first two actual writer events. On the third step it calls the frozen stage-zero scorer on the original prompt if the opening was an authenticated copy and the second event was a generated period. The third event uses the actual two commits as its preceding context. A negative score selects EOS and terminates the client. Zero retains the native proposal. A positive score requests another copy. The ordinary reader supplies no second authenticated source, so the client records that unresolved request and keeps the native proposal. The trigger sees the model’s own copy even if it was from the wrong semantic occurrence. Only the external grader knows the expected source or reference answer.

The primary grade checks that both opening events match the unchanged client in full, verifies every triggered third-step event against the unmodified writer, and compares the complete trajectories wherever the release kept the native emission. It separately computes exact replies through EOS and first wrong tokens. The secondary scope audit traces the frozen feature extractor’s requirement for a question-mark ID between the last blank-line separator and the assistant marker.
