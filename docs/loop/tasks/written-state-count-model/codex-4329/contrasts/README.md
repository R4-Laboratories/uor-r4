# Matched assertion and question edits

These are agent-authored examples for supervised source admission. Four template families contribute 240 training rows. Two separate template families contribute 120 development rows. Each family varies who was asked about, which fact comes first, value ownership, whether the two values share a token, and whether a statement about one person is affirmative, a denial, or an unanswered question. In the one-nonasserted-statement pairs, changing only the person asked about changes the required action between copy and NoRead. Thus the appearance of a denial or a question mark anywhere in the paragraph cannot solve the pairs.

Prompts are single ordinary user messages with no fact/query fence. Source membership is derived from the authored fact and byte span and verified against literal protocol-2 tokenization. Positive targets point to the exact original position in the complete serving prefix. NoRead examples leave that address absent while retaining both candidate token IDs. Both assignments of distinct values and a duplicate-ID condition are included. Rows also contain a reference reply through EOS for measuring the actual writer after source selection. The annotations are training and scoring inputs only. An ordinary serving comparison receives the raw text.

Build with `cargo build --locked --release --manifest-path contrasts/Cargo.toml`. Run `whole-turn-contrasts TOKENIZER.json NEW_DIRECTORY`, then `jq -s -f contrasts/check.jq NEW_DIRECTORY/train.jsonl` and the corresponding dev command. The development prompts are authored controls with repeated wording, and are kept separate from the natural human QA supply and any later blind conversational evaluation.
