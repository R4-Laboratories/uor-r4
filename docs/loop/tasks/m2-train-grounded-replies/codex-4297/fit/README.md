# Wick native transport proposals

Each invocation fits one round from a supplied 13,336-byte `UORSTT01` base. `strongest` and `all` receive the endpoint TRAIN packet. `ordered-all` uses the same all-rival update with the separately authenticated ordered-interval TRAIN packet. The binary reads the same typed `UORTXT01` layout for either representation. The run release binds each arm name to its packet digest and records the base, bank and label digests. The archived #4288 joint predictor and #4289 signed enrollment and measurement operate on that packet. Both remain on the device.

For the initial 128 TRAIN rows, the archived measurement reads the authored governor and all eligible different original sites in its signed tuple position under the exact base state. A strict rival costs less than the gold site. Each selected strict rival provides one unit distance subgradient per coordinate. The gold's nearest center votes toward the gold vector, and the rival's nearest center votes away from that rival vector. Equal coordinates contribute zero. The strongest arm uses the lowest indexed original site among tied cheapest rivals. The all-rival arms sum the attraction and repulsion votes over every strict rival. Each displacement uses the sign of the sum for that center coordinate. Every displacement saturates to i16. Unchanged and inactive proposals still occupy the same schedule position.

The device independently assesses the base and all 68 candidate states. On the first 128 rows it computes both objectives from the current nearest costs. `strongest_loss` sums the maximum strict deficit for each signed edge. `all_loss` sums the deficits over all strictly cheaper original sites. A deficit is gold cost minus rival cost. `tied_edges` counts equal-minimum edges with no cheaper rival and `equal_cost_rivals` also counts any equal-cost sites on edges with a cheaper rival. The joint predictor receives all original sites and scores full tuples on all 256 TRAIN rows. The caller joins the two endpoints of each pair against the enrolled exact source addresses and selects the next state using the study's election. Repeat the command with the elected state for a second round.

- `menu.jsonl` fixes groups in sign and slot order, then the whole bank. Each group takes steps 1, 2, 4 and 8, with IDs 0–67.
- `directions.jsonl` records the 32 signed integer vote totals for every sign and slot.
- `scores.jsonl` has the base with a null ID followed by all candidates. It records both losses, the signed edge win, loss and tie counts, the strict and equal-cost rival counts, and the number of changed i16 coordinates.
- Each candidate and the base have a `.state` native artifact, `.reader.jsonl` #4288 read with resolved original addresses, and `.edges.jsonl` #4289 signed diagnostics with both strict deficits and each eligible candidate as `[site,cost,center]`.
- `complete.json` records the arm, row counts, proposal count and the state size after all raw outputs close.

Stage the five source files to a new directory under the owned Wick fit root. Run `bash run-wick.sh build v1` and then `bash run-wick.sh finite v1 v1`. Use fresh versions for retries. The build pins the existing physical operators, compares their relevant SM89 assembly with #4292, scans device instructions and checks that no PTX is embedded. The finite command acquires the exclusive #4281 lease before launching synthetic cases. It verifies current-state rival selection, a changed strongest rival on the second round, distinct strongest and all-rival votes, original-address recovery, exchanged-address rejection, loss of a protected near identity at equal near count, artifact readback and i16 saturation. The archived reader and diagnostic binary replay the selected synthetic artifacts and match their full original-address reads and signed costs. Use the parent study release to launch production from the sealed executable under that same lease.
