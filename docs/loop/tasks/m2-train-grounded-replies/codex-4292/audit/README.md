# Independent Wick replay

The replay reads captured integer state and outputs. It leaves the proposals, election, held panel and writer capture to the registered measurement pipeline. It runs only on Wick as a reference comparison. The GPU captures are the measured results.

`run-wick.sh build vN` builds with the pinned packet implementation and joint reader from #4288 and the signed-edge reader from #4289. The build seals the exact Rust sources and binary. `finite-wick.sh PHYSICAL_VERSION AUDIT_BUILD_VERSION NEW_AUDIT_VERSION` checks the separately sealed physical finite output, byte-identical fresh retry, cold state, signed margin and joint original spans, then uses a changed signed cost to test failure.

`verify-train-wick.sh MEASUREMENT_VERSION AUDIT_BUILD_VERSION NEW_AUDIT_VERSION` reconstructs the first simultaneous update from the unmodified parent and TRAIN labels. It builds the canonical proposal order from the integer displacements. For every physically recorded unique batch, it reconstructs every full candidate state, compares the full signed and joint rows, and calculates the source pair IDs from the three original noun/reference addresses and both original signed governor addresses. It compares the complete winners and their parent and final state bytes. It checks the first protected rejection overall and among far-improving proposals against the raw earliest failing endpoint. Each receipt uses a new directory.

`verify-held-wick.sh MEASUREMENT_VERSION TRANSFER_VERSION GRADE_VERSION AUDIT_BUILD_VERSION NEW_AUDIT_VERSION` independently compares the four learned state readers against the fresh panels' grade. It compares the old, lost and gained pair identities and the preserved native/correct/exchanged control parity. The verified TRAIN receipt precedes the transfer permit, while the independent transfer receipt follows transfer and grade.

The fixture receipts for the release elections, enrollment and ordinary client are separate. `fixture-wick.sh WICK_RELEASE_METHODS NEW_AUDIT_VERSION` tests the production candidate/election/gate jq. `panel.jq` checks authentic EOS history and the invariant text and BPE tokens outside the two original governor spans of each opposed fresh pair. `client-fixture.jq` independently checks the 14 fixture wires and the distinction between exact EOS and a correct capped prefix.

The [supplemental Vast fixture](VAST-FIT.md) uses `verify-vast-finite-wick.sh RESTORED_PROVIDER_ROOT WICK_AOT_STAGE PROVIDER_JOB_LOG FINITE_SHA POD SESSION AUDIT_BUILD NEW_VERSION`. This verifies the mirrored lease, device, payload, logs and the sealed finite rows before invoking the same independent finite replay. The supplemental TRAIN audit first runs `run-wick.sh batch` on the restored provider device tree, then `verify-vast-train-wick.sh RESTORED_PROVIDER_ROOT PROVIDER_JOB_LOG SEALED_GRADE SEALED_BATCH_AUDIT NEW_VERSION` compares those original source identities and both elections against the frozen grader.
