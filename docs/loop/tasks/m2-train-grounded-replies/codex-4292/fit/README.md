# Score the frozen signed transport moves on Wick

The stage consumes the original mixed TRAIN geometry and labels, the parent `UORSTT01` state, and its first simultaneous mixed TRAIN update. It reconstructs the update on Wick with the #4289 signed nearest-center enrollment, measurement and repulsion kernels, then compares the full state to the recorded #4291 update. The 13,336-byte artifact carries both lexical banks and both transport banks, including their active counts and inactive coordinates. Candidate generation changes only the destination coordinates of a single active transport center in one sign. Each candidate starts from the same immutable round base and saturates to the i16 range. The existing #4288 attachment and joint-rank kernels read the result through the original byte and BPE addresses. The fixture compares the complete candidate bytes against independent expected bytes and every device source and edge record against the released command-line tools.

Run the binary under the inherited exclusive Wick lock. The production invocation takes exactly 256 TRAIN rows. It sums the signed unit-margin hinge across both signs on the first 128 common far rows. The device ranks all 256 prompts. This command emits every proposal and leaves election to the caller.

```sh
transport-proposals-sm89 WORD_BANK TEXT LABELS ORIGIN EXPECTED_STEP1 ROUND_BASE NEW_OUTPUT_DIR
```

`menu.jsonl` gives zero-based `id`, `kind`, `sign`, `slot`, `axis` and the 32-coordinate `delta`. Each nonzero coordinate projection appears in sign, slot and axis order, followed by each distinct nonzero complete-center projection in sign and slot order. A complete-center projection with one nonzero axis is the same move as its earlier coordinate projection and appears only once. `menu-summary.json` records the number of those duplicates. Every round uses the same IDs, even when a coordinate saturates and the proposal changes zero bytes.

`scores.jsonl` starts with the round base (`id` null), followed by the moves in menu order. The device reports `hinge`, `strict_wins`, `strict_losses`, `eligible` and `changed`. Each record has a raw `$id.state` (`base.state` for the round base), the original #4288 `$id.reader.jsonl` with decisions, original addresses and ranks including ties, and `$id.edges.jsonl` with the #4289 measurement, signed strongest rival and all tied rival sites for every TRAIN edge. `step1-replayed.state` is the device reconstruction of the expected first simultaneous checkpoint. `complete.json` appears when the pass has written its data.

On Wick, stage the source directory with a fresh name, then run `bash run-wick.sh build v1` and `bash run-wick.sh finite v1 v1`. The build pins the released dependencies, checks SM89-only code with no PTX, scans device instructions and compares the inherited kernels to their released disassembly. The finite fixture uses six synthetic prompts with two common-far endpoints. Two coordinate moves yield the same far loss improvement. The first keeps the original near pair. The second improves a different near pair while replacing both original winning noun addresses with rivals, preserving only the count. The second round replays the same menu around a center at both i16 limits. It also checks that a wrong step-one checkpoint aborts the pass and repeat invocations are byte-identical.
