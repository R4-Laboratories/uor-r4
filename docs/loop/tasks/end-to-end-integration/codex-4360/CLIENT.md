# Shortest ordinary-client route for UORBFY03

Source inspection at `d71296428615755fcdf9c8be55a712fe4e966a2a`. No model execution or implementation changes.

**Current entry points.** The `uor-chat` binary selects either the P4-only client, which requires embedded P4 in `--discrete`, or the full client with stack and discrete loaders. Its integer crate dependency disables native-vector's default features, and both V3 and its shared Butterfly operators sit behind `butterfly-research`. The generic Studio worker checks `UORLUT01` and the WASM bindings expose stack/discrete loaders. The Foundry Studio runtime loads `UORR4V13` in its own worker. The Tauri sidecar currently passes `--stack`. The antigravity V3 benchmark is the existing executable reference that opens raw V3 bytes. **Start with a one-shot text CLI.** Add a dedicated opt-in V3 serving feature in `uor-r4-integer` and an explicit V3 arm in its ordinary CLI surface. Keep the artifact codec and transition in `uor-r4-native-vector`. A finite prototype can use the full reference `ButterflyV3Model::step`; product promotion requires an audited inference compile surface, reusable scratch without steady-state allocation, and a raw-word differential against the reference. The current step builds full training caches and is the measured M1 speed bottleneck. When adding browser support, expose the same typed session through WASM and a format-specific worker capability. Keep stack session snapshots and V13 loading on their existing paths. [V3 session and output][state] · [V3 transition][step] · [Allocation and M1 evidence][report] · [WASM bindings][wasm]

**Bind the chat transport.** Require an approved manifest with checkpoint and exact tokenizer SHA-256, codec/protocol version, and the expected vocabulary and special IDs. Verify digests and size limits before decoding or exposing a session. The checkpoint codec checks magic, version, structural bounds, vocabulary bijection and an internal FNV-1a checksum. Its payload has no tokenizer identity or chat protocol field. The matched Gate 1 tokenizer SHA-256 is `a9fb13f70c69ffe5afed40c8251a8e702adf0b00732d35ccff9457a3309ee377`. Use `ByteBpeTokenizer` and literal role protocol 2 from the V3 panel builder. Share checked role/turn parsing with ordinary P4 where possible, then bind the authenticated V3 tokenizer and validate model vocabulary and special IDs. The model consumes tokenizer IDs and applies `vocab_perm` internally, then returns tokenizer IDs through `vocab_inv`. Decode the response as accumulated bytes or incremental UTF-8, since a piece may contain part of a code point. **Preserve recurrence and termination.** Cold-encode the complete messages through the assistant prefix for the first integration, including one BOS, EOS after each completed assistant turn, and the unfinished assistant opener. Prefill in order and use only the last prefill prediction to start greedy self-feeding. Preserve `carry`, `shift_hist`, and `tokens_seen` as the native V3 session. Read EOS from the bound tokenizer and check the expected EOS ID 1 and BOS ID 0. Keep EOS in trace while withholding it from text. Report EOS, invalid BOS and the cap distinctly. For a later warm multi-turn implementation, commit every actual token, including the real closing EOS exactly once, and require bit-identical cold/warm replay on identical token histories. The historical V3 generator returns EOS as a flag and stops before feeding it. A product wrapper retaining session state across turns must account for that boundary. **Bounded checks before trained replay.** A fixture-only slice can test golden protocol-2 prefix IDs, BOS and completed-assistant EOS placement, tokenizer byte decoding across split UTF-8, rejection of malformed/mismatched model and tokenizer packages, and reporting of EOS/cap/invalid BOS with a scripted output source. A separately scanned finite native fixture can later exercise a valid synthetic V3 codec round trip and compare exact session words, coarse route, PKM slots, hidden words and greedy IDs through CLI and WASM. Those checks establish import and transport behavior. Trained-checkpoint parity, time/memory, and open-ended dialogue quality remain separate evidence.
