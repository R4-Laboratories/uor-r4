# From measured integer prediction to a local conversational model

Lab: codex. Architecture review, 26 November 2026, against UOR-R4 main `e9b5580dd`. References #4064, #4063 and #2030. [Review order](ORDER.md)

## What did not work

Repeated interventions on sentence structure mapped a source-selection failure. The native reader got 0/128 new first/later pairs. Giving it the governing action and a list of genuine candidate nouns raised that to 15/128. Both repeated nouns remained available. Even with that help it recovered zero complete source tuples across 256 prompts. No reply was generated. The preceding run did fit integer weights on 64 training pairs and still got 0/128 new pairs. Keep these examples as error probes. The main training signal can come from the next observed token on varied text. [Learned-coordinate trial](../../m2-train-grounded-replies/codex-4303/REPORT.md) · [Supplied-source trial](../../m2-train-grounded-replies/codex-4305/REPORT.md)

The strongest current native model missed its held-out language target as well. On the separate `chat-v0-p2` corpus, P4 achieved **1.467631 bits/byte**, ahead of the earlier P1 model at 1.499106 and above the 0.90 target. Lower is better. This was teacher-forced next-token prediction. The project still has one of eight milestones closed. M2 requires the same native student to generate complete replies on at least 256/512 saved questions and on both sides of at least 52/128 fresh, opposite-role pairs. [P4 physical measurement](../../written-state-count-model/antigravity-17/REPORT.md) · [M2 acceptance](../../../../roadmap/items/m2-train-grounded-replies.md) · [Milestones](https://github.com/UOR-Foundation/uor-r4/issues/2028)

## What changed

**Use frozen P4 as the model-wide baseline. Give P5 the first opportunity to change learned geometry. Give Omega a real operator to accelerate in parallel.** One addresses which continuation gets probability mass. The other addresses the cost of evaluating the same state transition. The harmonic candidate can enter a matched comparison once it has causal train/decode parity. These recommendations use the existing written-state phase gates and M2–M8 acceptance criteria. ## The order of work

1. **Train and ship one change to ordinary next-token prediction.** Start at P4 with the pinned tokenizer, corpus split, count/cache experts and writer. Antigravity owns the P5 host implementation in #4306 and the planned Wick GPU qualification after its preregistration and FIT. The host PR has no P5 GPU training result. Its candidate code scores legal edits to S1 integer coordinates using the full-vocabulary Brier error of the mixed next-token mass. A coordinate edit can change the earlier occurrence chosen by Pick and the distance class that selects mixer weights. That gives this first P5 run a defined reach. Compare frozen P4, trained S1 and equal-trial random coordinates under the same token and search budgets. Retain the registered two-GPU-day gate of at least 1% held Brier improvement per GPU-day against that control with no BPB increase. Publish all, novel and response-only scores and a split for targets absent from the visible prefix. Failed transfer refreezes this S1 configuration. [P5 registration](../../../../research/reviews/pi-review-2026-11-16/DECISION.md#p5-the-scored-geometric-core) · [P5 implementation and open GPU work](https://github.com/UOR-Foundation/uor-r4/pull/4306)
2. **Make an accepted update observable after reload.** The serving loader binds the embedded trunk digest to the fit manifest and the Pick mixture to that manifest's digest. Regenerate those bindings against the trained D11 and rebuild the P4 package using the original frozen expert values. Replay cold on CUDA and through ordinary `uor-chat` on the M1. Compare masses, route, carry, read, original address and token IDs. Keep an untouched control and a deliberately stale binding that must fail. Show actual held prompts where a learned update changed, improved or worsened a free-running reply, with EOS or the token cap recorded. This catches the case where learning succeeds inside a scorer and disappears at deployment. [Loader bindings](https://github.com/UOR-Foundation/uor-r4/blob/e9b5580dd7b56d7b3760b9cdd5c502fba30616c0/crates/uor-r4-integer/src/discrete_count.rs#L260-L310) · [Native state contract](../../../../model/native-space-state-contract.md)
3. **Give the same predictor a learned route to grounded output and a route to novel words.** On grounded training turns, use original source addresses as auxiliary targets when available. From ordinary text, a bounded read should propose an authenticated original token/span, or abstain. Train its contribution to the same next-token mixture, score correct and wrong source alternatives, and feed each emitted token back through the same decoder. For text whose next token is absent from the current context, train shared, carry-conditioned continuation rows using actual next-token error. Use the existing S3/S6 machinery as a candidate and compare equal-byte token-context and reseeded geometry. Measure whether the correct continuation was excluded by admission or lost after admission before changing either. This second route tests whether learning goes beyond copying. Retain the 28 original source-pair guards as focused regressions for the selector branch. Qualify **ordinary** memory-on, memory-off, shuffled/wrong-address and supplied-gold controls on fresh text, unseen values, corrections, unsupported questions and both role orders. Grade grounded content across permitted phrasings and inspect free-running prose with blind human assessment alongside the registered deterministic M2 grader. The ordinary client receives no annotations, correct role, sentence frame or reference answer. [M2 gates](../../../../roadmap/items/m2-train-grounded-replies.md) · [S0–S6 design](../../../../research/reviews/pi-review-2026-11-16/DECISION.md#31-the-state-one-d85-integer-state-extending-the-d11-trunk)
4. **Test whether more training buys more capability.** Use the same deployable model family at three or more capacities and at least two data doses and seeds. Report both equal-token and fixed-wall-time comparisons, active and allocated parameter bytes, touched rows, peak VRAM, training positions/s, compute per held improvement, and complete generated replies. Split natural dialogue by conversation tree and prose by article/document before tokenization. Reserve new sources and task families to protect against repeated tuning on the research panels. Use the existing D87 and human-text assets and the registered scale work. If quality is flat within measured variation, identify admission, update coverage, optimizer search or data diversity from traces before paying for a larger run. More donor generation has its own decision. ## What would justify a larger change

A convincing Omega backend would reproduce raw UOR transitions and improve end-to-end time or energy at the same answers on the target. A convincing Omega **learning mechanism** would beat the frozen and trained UOR alternatives on fresh next-token and ordinary conversation tests at comparable data, active/resident bytes and compute. Arboris can enter first as a read-ahead hint. Only a later separately trained arm could establish that it improves a learned source decision. Replacing the model with Helix as published would bring dense floating-point transformer training into the core and require a different owner decision. The receipts currently justify the backend experiment. [Omega comparison and exchange proposal](OMEGA.md)

Frontier quality needs a named, dated target suite covering unassisted conversation, executable coding and reasoning with an agreed resource envelope. The project's “1B-equivalent” is a joint experimental target for integer state, predictive quality, replies, speed and parity. A billion kept tokens, a billion cells, fast decode or good compression individually cannot settle the capability claim. The first quantitative estimate available is P5's registered decision window of two GPU-days and its planning range of two to six GPU-days. A calendar estimate for frontier quality needs a reproducible scaling slope on those tasks. [Registered target definition](../../../../research/reviews/pi-review-2026-11-16/DECISION.md#2-the-final-definition-of-1b-equivalent) · [Compute and time model](COMPLEXITY.md)

For that suite, keep two dated scorecards. The first measures the model alone on new multi-turn explanations, factual grounding and correction, multi-step problems with checkable results, and execution-tested coding on projects held out by repository. Count ordinary answers, abstentions and failures. The second can measure the same artifact with exact memory, a local code runner or Lean, with tool calls and extra wall time shown. Agree which capabilities must approach which published frontier reference before using that label. Published figures currently give context. The charter postpones running neural comparators until an end-to-end native model works. [Research and comparison boundaries](../../../../../CHARTER.md#3-technical-constraints)

## Checks run at the head

The review also ran five finite vectors through the actual UOR Pick operator on native Apple M1 and in a local Chrome Wasm page. Both accepted all five and detected a planted wrong address with the same token ID. This is a portable, non-toy operator with a deliberately small synthetic input for the proposed Omega comparison. [Fixture and reproduction](OMEGA.md#a-public-operator-fixture-from-this-review)

The review compared immutable UOR source with the registered gates, P3/P4 measurements, section sizes, serving order and the training proposal. It inspected the UOR/LexLean public catalogues, Omega's published site map and component pages, the Git source and benchmark receipts, and the public references in the accompanying analyses. The operator and training proposals are prospective. The last training and hardware numbers in each table belong to their cited runs. No weights were changed, no GPU was rented, and no third-party driver was installed for this review.

## Plain summary

The laptop already runs a fast model that learns some next-token statistics. The next question is whether its trained geometry can carry meaning across new wording, choose a stored fact when appropriate, and generate a useful reply. Measure that on the saved model. Omega can independently reduce the cost of the same work if its backend beats the existing implementation under identical outputs.
