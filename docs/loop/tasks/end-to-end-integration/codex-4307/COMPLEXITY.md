# The complexity target and the harmonic experiment

## Define the variable before claiming the bound

Let `T` be distinct token positions presented in a training pass, `L` the context length, `D` the carry width, `P` the number of learned cells stored, `V` the vocabulary size and `K` the number of candidates or cells actually touched by a step. Keep epochs, layers, active operator dimensions and optimizer proposals visible in any quoted rate.

| Claim | What would make it true |
|---|---|
| Constant total time to train on arbitrary new material | A learner whose result can depend on every arbitrary input token must inspect that input in the worst case. Changing an unread token is an indistinguishable input to the learner. Reading a fresh corpus therefore costs at least Ω(T). Reusing a sufficient statistic, answering an existing checkpoint lookup or doing many operations in parallel changes the input or the latency metric. Count the original reads and work. |
| O(1) work **per incoming token** with respect to stored capacity or past context | Fixed-width carry, a bounded number of directly addressed operations, bounded vocabulary admission, bounded update fan-out and controlled lookup collisions could achieve this. An index with expected constant lookup needs a measured collision/miss distribution. Allocation, model loading, index construction, compaction, memory bandwidth and writing a full checkpoint still cost real work. State the quality and retention trade-off as history grows. |
| O(L log L) sequence mixing | A dyadic filter with lags 1, 2, 4, … below L applies about log₂ L shifted contributions per position and lane, giving O(DL log L) at fixed layer count and precomputed tap weights. With correctly retained history its per-token mixing work is O(D log L). A direct ring grows with the maximum lag. Fixed truncation can bound cost but caps the direct receptive field. A causal hierarchical summary can be tested at equal bytes and recall. |
| O(T log L) or O(T) **end-to-end training** | Profile tokenization, candidate admission and recall, forward read, output mass/rank, loss, search/credit, writes, synchronization and I/O. If each of these has the required bound and measured quality holds, the total can inherit it. In the current P4, production scoring and argmax visit all 4,095 legal tokens. The candidate P5 uses a full-vocabulary loss and coordinate trials. An efficient context mixer does not eliminate these costs. [P4 scoring and argmax](https://github.com/UOR-Foundation/uor-r4/blob/e9b5580dd7b56d7b3760b9cdd5c502fba30616c0/crates/uor-r4-discrete/src/kn_ceiling/runtime/p4_serving.rs#L1947-L1983) · [P5 scoring implementation](https://github.com/UOR-Foundation/uor-r4/blob/81db3c8e972207c586dd60905a9b486c44a1a334/crates/uor-r4-discrete/src/p5_brier_core.rs#L600-L709) |

For unit vectors, squared Euclidean chord distance equals `2 − 2〈x,y〉`, and angular distance is monotone in the same dot product. Switching distance names alone cannot reduce how many sites an exhaustive search visits. Geometry can change the cost by admitting a small set, supplying structured transports, sharing parameters across contexts or allowing a state update that touches few cells. An address collision, a missed correct candidate, or an enlarged training search can undo the gain. Measure recall of the correct candidate *before* reranking, the size and traffic of the accessed set, and the final trained output. Hardware improvement depends on arithmetic intensity and sustained bandwidth as well as asymptotic counts. [Roofline model](https://www2.eecs.berkeley.edu/Pubs/TechRpts/2008/EECS-2008-134.html)

## One way to try for bounded training work

**Index the two-token geometric code that Pick already reads.** Maintain a causal, incrementally updated bucket of earlier occurrences with exact offsets and successor IDs. Search a bounded number of buckets and postings, recording overflow, misses and recency tie-breaks. Compare against today's exhaustive Pick for source recall and held quality. In particular test many identical codes with different successors and long-distance corrections. A fixed posting cap gives bounded work but can remove the true source. An exact fallback that scans the entire context must be counted in both worst-case work and measured latency.

**Exploit the loss algebra before introducing an approximate loss.** For an observed token `y`, multiclass Brier is `1 − 2p_y + Σ_i p_i²`. If an edit changes only a small set of final masses and a background sum of squares is already available, its squared-mass change is the sum of `2p_i Δ_i + Δ_i²` on that set. A shared default mass can also be accounted for with its multiplicity. P5 already exploits a restricted form by preparing scores for the possible Pick outcomes. A changed context bucket can replace an entire expert distribution, and integer division, clipping, remainder assignment or a different normalizer can change additional scores. Charge that setup to the step. Compare the proposed sparse update with the existing integer full-vocabulary loss on exact raw words, including ties and saturation. Pay separately for index construction, optimizer search and the full checkpoint. This tests whether sparsity survives the *learning* path.

If a bounded read lowers traffic while worsening target admission, repair or widen the index and plot the quality–cost curve. If admission is stable and only the ranking fails, train the affected continuation weights. If changing those weights improves training but fails on fresh sources, change representation or training data before buying more compute. A lower measured cost to reach the same held quality would support the intended design.

An external result suggests a concrete allocation experiment. Cheng and colleagues used deterministic n-gram addressing into a large learned memory and varied how many parameters went to lookup versus computation at matched total parameters and FLOPs. Berges and colleagues measured sparsely accessed trainable memory in another model family. In R4, about 95.4% of P4 bytes currently hold counts. After the P5 decision, compare a small set of **fixed-total-byte** configurations that move capacity from static counts into learned carry-conditioned continuation rows. Match active accesses as well as training tokens, retain a frozen-row control for each allocation, and score targets absent from the prefix and free-running replies. This tests a property of R4 that the external transformer results cannot establish. [ACL 2026 conditional memory study](https://aclanthology.org/2026.acl-long.226/) · [Memory Layers at Scale](https://arxiv.org/abs/2412.09764)

## A falsifiable spherical-harmonic arm

The November design deferred degree-two-and-higher harmonics pending geometric evidence. Reopen a bounded comparison under a specific hypothesis: a small learned bank of coefficients over causal lags can improve prediction on new contexts at equal active bytes and cost. The exact domain matters. A time filter using zonal Legendre polynomials on S² is distinct from a hyperspherical operator on the unit quaternions S³, and from an eight-dimensional unit port on S⁷. A Hopf projection alone drops fibre information. Fixed coefficient gains form a basis or filter. The receipt should identify which coefficients, transport coordinates and output weights actually moved and were reloaded. [Original decision](../../../../research/reviews/pi-review-2026-11-16/DECISION.md) · [NIST spherical harmonics](https://dlmf.nist.gov/14.30) · [Hopf construction](https://arxiv.org/abs/2212.01642)

**There are two different harmonic experiments.** The archived September probe pooled by the nine conjugacy classes of the 120-element binary icosahedral group. On synthetic held corruptions its hand-set filter raised corrupted-address accuracy from 0.13 to 0.23 and lowered clean accuracy from 0.55 to 0.15. The recorded clean-trained ternary arm also lost clean accuracy. It was an address-memory experiment. [September experiment, controls and follow-ups](../../../../../archive/evidence/native_geometric_spherical_harmonic_kernel_2026-09-19.txt)

OpenCode's November UOR worktree instead fits a text model with a fixed degree-four time filter. Its author-reported two-seed, 512-context comparison places both the short causal filter and the harmonic filter ahead of no mixer on teacher-forced full-table rank. The difference between filters is inside the reported variation, and GPU sharing differs across arms. We also traced whole-window prefill and cached single-token decode: the per-call horizon changes the coefficients and a length-one call has no previous taps. The first replay experiment below can detect both. This review did not reproduce the training run. The exact November revision was unavailable from public UOR GitHub at the review date; the author report, exact revision, numbers and line references were retained in the owner-visible companion. They are separate from the public archived experiment and from the D85 product evidence.

1. Seal the actual tap coefficients or deterministic integer generator, reference horizon, learned cells, scale, rounding, overflow rule and session history in the artifact contract. At a fixed model configuration a prefix must yield the same next-token state when fed in full, in irregular chunks, one token at a time and after a restart. Also test suffix extension: a longer call with the same prefix must preserve the prefix's existing states. Comparing two equal-length calls with different future tokens tests a different property. Two concrete mistakes to catch are deriving lag weights from the current call length and dropping all previous lags on a one-token cached step. If a geometric partition is used at output, move one token deliberately between cells and require the same map to drive centroid formation, admission, training credit and serving.
2. Compare no mix, the existing short FIR, equal-support dyadic flat/recency weights, a permuted same-support control, fixed harmonic weights and learned harmonic weights. Fit only on TRAIN. Keep vocabulary admission, width, initial state, lag support for the matched arms, bytes touched and update budget identifiable. Freeze once and score new conversations and documents with at least two seeds. Grade BPB and integer Brier, non-copy next targets and complete free-running replies, including long-distance contradictory facts. Report teacher-forced rank in its own units if the prototype uses it. Require a benefit over the best matched cheaper alternative, or retain that simpler configuration.
3. Sweep context and capacity independently, for example 256/512/1,024/2,048 context on the same GPU. Give batch, positions, response targets, effective vocabulary, training wall time, evaluation wall time, peak training/evaluation VRAM, optimizer bytes and checkpoint size. Profile candidate search and peak output buffers separately. Make a second comparison at fixed wall-time budget. Test the actual memory-limiting phase. A smaller activation tensor does not compress stored parameters.
4. Measure the same accepted integer artifact on the native client and in an offline worker. Distinguish a fixed harmonic basis from learned coefficients, a forward-only approximation from a trained result, and a tokenizer rank metric from a generated response. Published selective-state and recall/throughput studies give experimental precedents for measuring long-context trade-offs. Their neural implementations are outside the UOR native path. [Selective state spaces](https://arxiv.org/abs/2312.00752) · [Recall and throughput tests](https://proceedings.mlr.press/v235/arora24a.html)

## Device and time budget

- **On the 4090**, time a warm production update that changes a persisted weight. Log useful held progress per GPU-hour, input tokens/s and supervised target tokens/s, compile/load/evaluation fractions and bytes read and written. A claimed improvement on a GB10 or different precision needs its own 4090 measurement. Timing one billion processed positions at 10k/s gives 27.8 hours, at 100k/s 2.78 hours. At 100k/s, one trillion would take about 116 continuous days for one pass before evaluation or retries. These are unit conversions. No R4 training rate of that magnitude is assumed. [GPU capabilities](https://developer.nvidia.com/cuda/gpus)
- **On the 16 GB M1**, P4 already fits and decodes quickly. Its roughly 3.8 GB count section dominates the pack. Profile cold validation and count-table access. Evaluate a lossless indexed/sharded count representation first. Profile alternative smaller models at equal accuracy or state their measured loss. A 4 GB training file, a 4 GB address space, and 4 GB of device memory are different budgets. [Pack manifest](../../written-state-count-model/antigravity-17/evidence/pack_manifest.json)
- **In the browser**, Wasm32 offers at most 4 GiB in one linear memory. The P4 package and tokenizer alone would leave about 293 MiB of that mathematical ceiling if copied into the same memory. Runtime heaps, JS staging, duplicate copies, GPU uploads and browser budgets matter. Default WebGPU limits include 128 MiB per storage binding and 256 MiB per buffer; request supported limits or use smaller tiles. Measure first download, trusted cold open, warm offline restore, prefill, decode, peak resident memory and exact replay. Avoid pinning all the shards in both JS and Wasm. Establish a smaller browser profile empirically if paging misses the latency goal. [Wasm32](https://v8.dev/blog/4gb-wasm-memory) · [WebGPU limits](https://www.w3.org/TR/webgpu/#limits)
- **For capability scaling**, plot held quality and successful full replies against tokens, wall time, evidence-backed energy and active/resident model bytes. Predeclare a target suite and draw later examples after model selection. Low-bit language models demonstrate CPU serving is feasible; one public 2B-class release used four trillion training tokens. Published compute-optimal fits concern the architectures and data in those studies. Neither number supplies an R4 data requirement or a frontier ETA. The decision about a larger run belongs to R4's own measured learning curve. [BitNet technical report](https://arxiv.org/abs/2504.12285) · [Compute-optimal empirical study](https://arxiv.org/abs/2203.15556)
