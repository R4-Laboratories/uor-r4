Construct whole-document components by transitive union over original conversation ID, domain/filename, and the SHA-256 of the complete normalized passage. Do not blanket-exclude all unconsumed turns of prior documents from other source components solely by the question string. Record exact prior-turn screens and any unsupported histories.

Before considering eligibility or any label, assign each nonexcluded complete component to TRAIN or held by independent hash rank threshold 80/20: SHA-256 of ASCII uor-r4-natural-pairs-v1, a zero, ASCII component-split, a zero and the sorted component roster IDs joined by zero bytes. First two bytes interpreted big endian, values below 52429 TRAIN. A normalized question family belongs to the split of its family representative component, chosen by minimum family-owner hash over the full eligible-domain article inventory after source exclusions, including turns never admitted but with valid original turn order. Hash payload is the normalized question followed by zero and sorted component IDs joined by zero. The normalized family definition is the existing #4361 alphanumeric/lowercase/whitespace normalization. Exclude candidate turns outside their assigned family split. Exact literal UTF-8 question equality remains mandatory to pair. No seed changes, split-packing optimization, manufactured question or answer, rewritten history or data duplication.

Consider every original third-or-later turn with contiguous preceding original question/assistant reply pairs. Preserve the complete original story in the first user message, exact authentic question and response text, prior assistant EOS, canonical literal roles, and target assistant EOS. Both sides must have different normalized complete answer strings and different first content IDs. Count candidate pairs across disjoint original components and report the restricted same-turn-ordinal and near/far supply. Report each stage before partition and the final component-only and component-plus-family splits. In each final split commit a deterministic greedy packing: sort literal question bytes, then component and turn ordering, pick disjoint components globally, and record the ceiling min(unique participating components / 2, sum per question of component count / 2) alongside it. Near/far and same-ordinal readings are diagnostics over the same strict eligibility. Output only safe aggregates, private source offsets, evidence text, role messages, exact tokens and digests on Wick. Classify the result as data construction only.
