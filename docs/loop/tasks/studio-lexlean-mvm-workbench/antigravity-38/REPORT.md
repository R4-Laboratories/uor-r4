  2. `CRITICAL-2`: Local `old_value.clone()` and `incumbent_lit` clones elevated `Arc::strong_count(b)` to `>= 3` (`>= 4` in `write_range`) before sole-owner accounting, and `p_cost` charged `0` for keeping a sole-owner `Shared` page. An initial R1 fix attempt left `write_range`'s own `old_value.clone()` active (`sole_owner_overwrite_in_place_range_write_and_json_handle_guards` panicked at line 229 with `-4`). Fixed cleanly via `apply_page_value_keep_old` returning the uncloned overwritten `Value`, `rb_map` rollback-pin tracking (`Arc::strong_count == 1 + rb_count_of(ptr)`), and `PAGE` sole-owner costing.
  3. `MAJOR-3`: Async `getVramPackStore()` in [`uor-v13-worker.mjs`](../../../../../web/studio/foundry/studio/shell/uor-v13-worker.mjs) could allocate a store handle after `finally` on cancellation, and `drainStreamMount` left `pendingMountPacks` entries in `vramPackStore`. Fixed with `loadDisposed`, awaiting `vramPackStorePromise` in `finally`, and `deleteFallbackPack(pack.file)`.
  4. `MAJOR-4`: `createVramStore(..., { maxPages: 0 })` left `allocInterval` comparing against `0`, and `| 0` wrapped integers `>= 2^31`. Fixed with explicit default resolution (`65536` / `64 MiB`) and `requireI32NonNeg`/`requireSafeNonNegInt` guards.
  5. `MAJOR-5`: `run_from_json` cast `u64`/`i64` without `try_from` bounds checks (`wasm32` truncation risk). Fixed via checked `json_i32` and `u64 <= MAX_TRANSFER_BYTES as u64` validation.
  6. `MINOR-6..9`: Added 24-bit generation tags in `VramRegistry` handles + `ERR_CAPACITY` on full slots, deferred hit/write increments until after verify and restored stats on `write_range` rollback, used `(ptr as u32 as usize)` casts in `abi.rs` and `packed === -1n` unsigned bit masking in `vram-store.mjs`, and note that `ORDER.md`'s `foundry_status` item does not correspond to an existing function in [`host.js`](../../../../../web/studio/foundry/studio/shell/host.js), so vRAM telemetry is exposed via `window.__uorR4.vram` and `VramStore.stats()`.
